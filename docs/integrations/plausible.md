# Plausible

Проверено: 24 октября 2026 года. Статус: исследовано; адаптер не реализован.

## Подключение и событие

Использовать актуальный snippet конкретного сайта из панели. Новый скрипт отличается от старых extension-based рецептов; отправка в несколько dashboards одновременно для него удалена. [Переход на новый скрипт](https://plausible.io/docs/script-update-guide).

Вызов: `plausible(name, { props: properties })`. [Параметры события](https://plausible.io/docs/custom-props/for-custom-events). Поддерживаются скалярные custom props, до 30 свойств; объекты/массивы не принимаются. [Типы и лимиты](https://plausible.io/docs/custom-props/introduction).

## Дубли, готовность и локальная работа

Существуют CSS event-классы и автоматические измерения. Их совместное использование с нашей отправкой требует исключения дублей. [Custom events](https://plausible.io/docs/custom-event-goals). В актуальных настройках есть autoCapturePageviews, captureOnLocalhost и transformRequest. [Конфигурация](https://plausible.io/docs/script-extensions).

## Предлагаемый адаптер

Передать готовую функцию, сформировать props без глобальной регистрации свойств. Не обещать независимые аккаунты через window.plausible и не обходить ограничение нового скрипта старой рецептурой. Официальный npm-путь, точные ограничения имени и подтверждение результата требуют отдельной проверки перед реализацией.

Политика приложения: filter перед отправкой, mock в тестах, локальная отправка выключена; установку SDK и выбор автоматических измерений выполняет приложение. Вызов функции не считается подтверждением появления цели в панели.

Приёмка: обёртка props, scalar-типы, лимиты, запрет второго native-пути; затем проверка цели и параметров тестового сайта. Из-за версии скрипта и адресации — второй набор, после GA4/Umami.
