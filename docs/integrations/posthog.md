# PostHog

Проверено: 24 октября 2026 года. Статус: исследовано; адаптер не реализован.

## Подключение и событие

Есть snippet и пакет posthog-js, инициализация с project token/api_host. Именованные клиенты создаются третьим аргументом init; документация предупреждает, что multi-instance не основной сценарий. Есть opt_out_capturing и настройки автоматического сбора. [Browser setup](https://posthog.com/docs/libraries/js).

Вызов выбранного клиента: `client.capture(name, properties)`. Текущий reference указывает CaptureResult либо undefined; это не Promise подтверждения приёма. [Capture API](https://posthog.com/docs/references/posthog-js).

## Предлагаемый адаптер

Передавать уже инициализированный именованный клиент и ограничивать mapping event-свойствами. Не использовать register для свойств одного события: это другой уровень состояния. [Event usage](https://posthog.com/docs/libraries/js/usage). Числовые лимиты event payload в этом обзоре не подтверждены — проверить перед реализацией, не заимствовать из GA4.

## Дубли и приёмка

Наше правило: приложение явно выбирает autocapture/pageviews и SDK opt-out; несколько именованных клиентов не должны автоматически собирать один click каждый. SDK-возможности и defaults зависят от выбранной конфигурации, поэтому адаптер не инициализирует их сам. [Настройки и несколько экземпляров](https://posthog.com/docs/libraries/js).

Локальные тесты — mock; далее отдельный проект. Проверить capture args, именованный клиент, не-Promise результат, отсутствие повторов и отказ одного получателя. Readiness, буфер SDK и путь подтверждения в панели фиксировать на версии, выбранной для реализации. Наш filter не заменяет управление полным SDK.
