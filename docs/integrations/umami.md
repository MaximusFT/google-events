# Umami

Проверено: 24 октября 2026 года. Статус: createUmamiReceiver реализован и экспортируется библиотекой, проверен с подставными клиентами; реальный SDK/панель этой версией ещё не подтверждены.

## Подключение и событие

Основной подтверждённый путь — script с website ID из настроек сайта. [Подключение](https://docs.umami.is/docs/collect-data). Event API: `umami.track(name, properties)`; также доступен custom payload. В таблице event data указаны строки до 500 символов и объект до 50 свойств. [Функции и типы](https://docs.umami.is/docs/tracker-functions). Имя события ограничено 50 символами. [События](https://docs.umami.is/docs/track-events).

## Автоматический сбор и окружение

Есть native data-umami-event, автоматические pageviews и настройки data-domains/data-before-send. Отключение auto-pageview отличается от полного auto-track. [Конфигурация](https://docs.umami.is/docs/tracker-configuration). Наш вывод: не оставлять native event-тег на действии, которое отправляется нашим адаптером; домены и разрешение отправки задавать явно.

## Реализованный адаптер

API и примеры: [ADAPTERS.md](../ADAPTERS.md). Настройки getClient/name/filter/transform; первый адаптер принимает плоские примитивные data, сохраняет boolean и проверяет лимиты имени/строк/числа свойств. Недоступный клиент отклоняет текущую отправку без скрытой очереди; следующий вызов может получить готовый SDK.

Передавать готовый клиент и map события; не переносить домен ma-x.im и contact-click из пилота. Несколько независимых website-клиентов через один window.umami не подтверждены выбранными страницами: не объявлять такую возможность до SDK-теста. npm-клиент в первый набор не выбран.

Документация функций не даёт нам основания обещать Promise-подтверждение серверного приёма. Readiness/тип результата проверить на зафиксированной версии скрипта; базовый адаптер не должен бесконечно ждать SDK. Локально — mock и исключение домена, перед отправкой — актуальный filter.

Приёмка: name/properties, лимиты, отсутствие native-дубля, поздний/отказавший клиент, изоляция dataLayer, затем событие в тестовой панели. Пилот: [отчёт](../SITE_PILOT.md).
