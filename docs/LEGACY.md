# Legacy: Google Events

Совместимый режим `createGoogleEvents()` сохраняет атрибуты `data-gtm-*` и `data-ecomm-*`. Для новых интеграций используйте нейтральный `createTracker()` из [основной документации](../README.md). Этот документ описывает только legacy-режим.

## Локальный запуск

Для разработки: Node.js 22 или 24 актуального patch-релиза. Проверки текущих изменений также прошли на Node.js 20.19.5; тестовый jsdom 27 требует Node.js 20.19+, 22.12+ либо 24+.

```sh
npm ci
npm run dev
```

Откройте адрес, который выведет Vite. В демо три кнопки одного товара, два получателя и переключатель ошибки второго получателя. Это UI-взаимодействия, а не подтверждённые сервером добавления в избранное.

```sh
npm run typecheck
npm test
npm run test:package
npm run check
```

`npm test` собирает библиотеку и проверяет её в Node test runner с jsdom. Это базовые регрессионные проверки; отдельный набор тестов в реальных браузерах ещё предстоит добавить.

`npm run test:package` проверяет уже собранный tarball: состав файлов, установку в чистый проект, ESM/CommonJS и типы в режиме NodeNext. `npm run check` запускает все проверки в нужном порядке.

## Использование

```ts
import { createGoogleEvents } from '@maximusft/google-events';

const tracker = createGoogleEvents();
tracker.init({ tags: { category: 'category' } });
// При размонтировании приложения:
// tracker.destroy();
```

Default export и именованный `googleEvents` — общий экземпляр для совместимости. Фабрика создаёт экземпляры с независимыми настройками. Для CommonJS: `const { createGoogleEvents } = require('@maximusft/google-events')`.

```html
<section data-gtm-event
         data-ecomm-product-id="SKU-AbC"
         data-ecomm-product-name="City Shoes"
         data-gtm-category="Shoes">
  <div data-gtm-link-place="modal">
    <button data-event="favorite_add" data-ecomm-event-name="add">
      В избранное
    </button>
  </div>
</section>
```

Результат в `window.dataLayer` включает:

```js
{
  action: 'click',
  event: 'favorite_add',
  data: {
    'link-label': 'В избранное',
    'link-place': 'modal',
    'link-type': 'button',
    'link-url': '@В избранное',
    'page-area': '2',
    restriction: 'public',
    category: 'Shoes'
  },
  ecommerce: {
    'event-name': 'add',
    'product-id': 'SKU-AbC',
    'product-name': 'City Shoes',
    'product-position': 'modal'
  }
}
```

`dataLayer` сам по себе не отправляет данные в GA4. Нужны настроенные GTM-теги или иной потребитель. Ecommerce-формат здесь — существующий формат библиотеки, не готовая схема GA4.

## Получатели событий

```ts
import {
  createGoogleEvents,
  createDataLayerReceiver,
  createCallbackReceiver,
} from '@maximusft/google-events';

const tracker = createGoogleEvents({
  receivers: [
    createDataLayerReceiver(),
    createCallbackReceiver({
      name: 'custom-analytics',
      filter: (event) => event.event === 'favorite_add',
      transform: (event) => ({
        name: event.event,
        properties: {
          productId: event.ecommerce?.['product-id'],
          placement: event.data['link-place'],
        },
      }),
      send: (payload) => {
        // Замените на вызов SDK своей аналитической системы.
        console.log(payload);
      },
    }),
  ],
  onError: ({ receiver, phase, error }) => {
    console.error(receiver, phase, error);
  },
});
tracker.init();
```

`receivers` и `onError` задаются в фабрике или `init()`. Без `receivers` используется один dataLayer-получатель. Явный список заменяет его; `receivers: []` позволяет только собирать и возвращать данные. Повторный `init()` без этих настроек сохраняет прежних получателей; `onError: undefined` возвращает стандартный вывод ошибок в console.error. Имена получателей должны быть непустыми и уникальными.

Каждый получатель получает собственную копию текущего события и контекста отправки. `filter` синхронно решает, нужен ли ему этот event; `transform` синхронно преобразует его в любую схему, тип которой выводится TypeScript. Эти функции не меняют данные других получателей или payload, возвращаемый трекером. `send` возвращает void либо `Promise<void>`; асинхронные получатели запускаются независимо.

Ошибки filter, transform и send не блокируют остальные получатели. `onError` получает имя получателя, исходный event, ошибку и фазу: `filter` либо `send` (включая transform). Ошибка самого onError выводится в консоль и не прерывает доставку. Повторов и гарантии доставки на сервер нет: результат SDK определяет фактическое завершение отправки.

`trackElement()` и `dispatchEvent()` возвращают собранное событие синхронно. `await tracker.flush()` ожидает завершения отправок, уже начатых к моменту вызова, включая обработку отказов; не является подтверждением успешной доставки. Асинхронный onError имеет собственную обработку ошибок, но flush не ожидает его завершения. `destroy()` снимает DOM-подписку и позволяет начатым отправкам завершиться.

DataLayer-получатель использует окно документа события, что позволяет работать с iframe без общей глобальной очереди. Можно задать `window`, `layerName`, `filter` и `transform`. Существующий объект с методом push сохраняется; несовместимое значение очереди вызывает диагностируемую ошибку вместо перезаписи.

Для собственного адаптера достаточно реализовать `EventReceiver`: `{ name, filter?, send(event, context) }`. Контекст содержит исходный document; фильтры и callbacks должны учитывать, что прямое изменение самого DOM остаётся изменением приложения.

## Правила контекста

- `data-gtm-event` обозначает область. Его значение остаётся маркером, не именем действия. `data-event` на действии задаёт имя; по умолчанию используется DOM-action.
- Ближайшая область ограничивает все поля, включая ecommerce и пользовательские tags. Собственные данные области включаются; вложенная область не наследует внешнюю.
- Для обычных полей ближайший атрибут перекрывает родительский, включая явно заданную пустую строку. Пустая строка исключается из payload, но не заменяется значением предка.
- `component-name`, `component-type`, `link-hierarchy` остаются цепочками `раздел > элемент`. Атрибут `<поле>-root`, даже пустой, останавливает только цепочку соответствующего поля. Для общей границы используется `data-gtm-event`.
- `tags: { output: 'source' }` добавляет в `data.output` ближайшее значение `data-gtm-source`. `map` переименовывает уже собранные поля.
- Значения атрибутов остаются строками. Регистр сохраняется; принудительной типизации пока нет. Нормализатор сохраняет числовой 0, false и массивы для переданных программно данных.
- `data-gtm-off` на действии или предке внутри области отключает событие по присутствию атрибута. Checkbox, radio и обычные поля автоматически больше не отключаются.
- Контекст читается заново при каждом событии. Новые элементы внутри области работают без повторной инициализации.

## Жизненный цикл и ручной режим

```ts
tracker.init({ root: document.querySelector('#app')!, automatic: false });
tracker.trackElement(button); // Возвращает payload либо false.
tracker.destroy();
```

`init()` сначала снимает прежние обработчики экземпляра. Повторная инициализация сохраняет и дополняет настройки `map`/`tags`; для чистой конфигурации создайте новый экземпляр. `destroy()` снимает обработчики, сохраняя настройки и возможность ручной отправки.

При автоматическом сборе `root` ограничивает подписку и поиск области. Вне него ничего не отслеживается; внутри должна присутствовать область `data-gtm-event`. Ручной `trackElement()` использует ближайшую область самого переданного элемента независимо от корня автоматической подписки. `dispatchEvent(element, root)` задаёт границу явно.

Импорт безопасен без `window`/`document`; `init()` без доступного DOM возвращает false. Слушаются click, focusout, Enter для legacy search-полей и change для select. Слушатели работают в фазе всплытия: остановленное до корня событие до библиотеки не доходит. Два экземпляра с пересекающимися областями подписки могут отправить два события.

Открытые shadow roots и slots поддерживаются сборщиком и проверены в jsdom. Закрытые roots скрывают внутренние элементы. Portals наследуют контекст фактического DOM-расположения. Для iframe нужен экземпляр в документе iframe; междокументного моста нет.

## Изменения поведения относительно исходной 0.2.0

Сохранены имена атрибутов и форма GTM-payload, но исправления меняют некоторые результаты: регистр данных/URL сохраняется, поля не выходят за область, повторные изменения форм учитываются, кнопки отправляются сразу без задержки 500 мс. `data-gtm-off` действует и на предках. `tags` с разными именами output/source теперь читает source. Select отправляет change вместо некорректного focusout-payload. Эти изменения нужно учесть при миграции существующей разметки. Публичный релиз с новой семантикой ещё не опубликован.

Legacy-переключатель `data-gtm-drawer-inverse-name` и определение search по CSS-классу пока сохранены. Их замена относится к следующему этапу контракта событий.
